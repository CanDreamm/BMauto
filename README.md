# BMauto — бот сообщества ВК

Python 3.12+. Черновики публикаций в ВК, задания из Google Таблиц, материалы на Google Диске. Яндекс не используется.

## Что реализовано

1. Пользователь пишет «Начать» в личных сообщениях сообщества и выбирает проект.
2. Сразу при выборе проекта бот читает таблицу и показывает будущие даты **в два столбца**, затем кнопки **«Настройки»** и **«Все проекты»**. По 12 дат на страницу. Одинаковые даты в разных строках остаются отдельными заданиями.
3. По выбору даты показывает все непустые поля **выбранной строки**. Если под «все заполненные строки» подразумеваются несколько строк на одну дату, это потребует уточнения группировки.
4. «Сгенерировать текст» запрашивает дополнение. Концепция + промпт проекта + поля задания + дополнение отправляются в GenAPI. Повторная генерация заменяет текст и оплачивается отдельно.
5. «Загрузить фотографии» принимает до 9 уникальных JPEG-фото ВК несколькими сообщениями. Превышающая лимит партия отклоняется. Используется наибольший размер фото, доступный в сообщении; ВК может сжимать изображения. Документы-вложения и внешние ссылки не принимаются.
6. «Отправить в таблицу» создаёт папку с датой в папке проекта, загружает `publication.docx` и фото. При `public_read: true` даёт всем по ссылке доступ на чтение и записывает URL в столбец ссылки. `.docx` — согласованный формат Word.

Все настройки проектов задаются **через бота ВК** и сохраняются в SQLite. Список проектов разбит на страницы. Черновик общий для операторов одного задания. Первая версия обрабатывает операции последовательно одним процессом; генерация блокирует обработку следующих сообщений до завершения. Запускайте только один экземпляр на одну базу.

## Установка

```sh
cd /workspace/BMauto
uv sync --frozen --extra test
cp .env.example .env
```

Команды копирования выполняйте только если локальных файлов ещё нет. Все токены, OAuth-файлы и черновики исключены из Git. Не отправляйте ключи в чат и не коммитьте их.

## Создание и настройка проектов в ВК

Напишите «Начать» → «Создать проект» и введите **только название**. Проект сразу сохранится. Его главный экран — даты в два столбца, «Настройки» и «Все проекты». Если таблица ещё не указана или Google не подключён, дат пока нет, но две нижние кнопки остаются доступны.

Всё остальное находится **только внутри «Настройки»**: название, концепция, промпт, подключение Google, таблица, выбор вкладок, папка, названия столбцов, доступ по ссылке, часовой пояс и участники. Поля разбиты на страницы. При выборе поля видно его текущее значение; после сохранения бот возвращается к настройкам. Отдельного промежуточного меню перед датами нет. По умолчанию: автоматические вкладки по месяцам, столбцы «Дата»/«День недели»/«Ссылка», часовой пояс Europe/Moscow, публичная ссылка на материалы. Настройки меняет владелец или администратор; участникам они доступны только для просмотра. Пустые значения, повторяющиеся названия столбцов и неверные ссылки отклоняются без изменения данных. Одновременное редактирование не перезаписывает более свежие настройки другого оператора.

### Вкладки по месяцам

Вкладки называются «Январь», «Февраль», …, «Декабрь»; регистр букв не важен. Бот выбирает текущий месяц по часовому поясу проекта и показывает его будущие заполненные даты. В последние **7 календарных дней** месяца добавляются будущие даты из следующей вкладки. Если в текущем месяце будущих заданий больше нет, следующий месяц подключается сразу. Декабрь → январь переключается с учётом нового года: в строках должны стоять полные даты нужного года.

В «Настройки» → «Когда брать следующий месяц» можно изменить порог (0–31). В «Выбор вкладок» режим по умолчанию «Авто»; старые значения с названием месяца или «Лист1» также включают автоматический выбор. Для прежних таблиц с одной другой именованной вкладкой сохраняется фиксированный режим.

Ссылка на материалы записывается в **исходную вкладку и строку выбранного задания**. Идентификатор вкладки сохраняется при выборе даты: смена месяца или переименование вкладки не направят ссылку в другой месяц. Черновики разных вкладок разделены. Если следующая вкладка ещё не создана, бот показывает доступные даты и пояснение; вкладки автоматически не создаются. Если данные текущей вкладки некорректны, ошибка показывается отдельно, без молчаливого пропуска.

Кнопки задания зависят от готовности черновика: генерация — после заполнения концепции и промпта; отправка — при наличии текста и папки Google Диска; загрузка фото скрывается после 9 изображений или начала выгрузки. После публикации остаются просмотр черновика и навигация. Ввод дополнения и загрузка фото показывают только кнопки текущего шага. «К датам проекта» возвращает к датам, «К заданию» — к выбранной публикации. Возврат из ввода настройки отменяет несохранённое изменение. Можно также написать «Меню» или «Начать».

`config.json` **больше не нужен** для запуска или настройки проекта. Если он остался от прежней версии, его проекты импортируются при запуске только при отсутствии такого ID в базе. Изменения из бота не перезаписываются старым файлом. Файл служит только для совместимости; редактировать его не нужно. Нетронутый демонстрационный «Пример проекта» больше не импортируется и удаляется из базы при обновлении. Пользовательские проекты и изменённый пример сохраняются.

Создавать и менять проекты можно до подключения Google и GenAPI. Для запуска диалога нужны `VK_TOKEN`, `VK_GROUP_ID`, `VK_ALLOWED_USERS`. На сервере один раз настраивается OAuth-приложение, а аккаунт Google для каждого проекта подключается кнопкой в боте. Секретные JSON-файлы и токены в переписку ВК не отправляются.

После изменения настроек бот попросит заново открыть даты, чтобы не использовать старое задание с новыми настройками. При изменении таблицы, вкладки, папки или режима доступа используются отдельные новые черновики: материалы прежнего назначения остаются в базе и не отправляются автоматически в новое место.

## Настройки ВК

- Включите сообщения сообщества, клавиатуры бота и Bots Long Poll API с событием `message_new`.
- Создайте токен сообщества с правами сообщений и управления сообществом для `groups.getLongPollServer`.
- Заполните `VK_TOKEN`, числовой `VK_GROUP_ID`, список числовых `VK_ALLOWED_USERS` через запятую в `.env`. Это **администраторы бота**, имеющие доступ ко всем проектам.
- Бот отвечает администраторам и приглашённым участникам в личной переписке с сообществом. Беседы не поддерживаются. Создавать проекты могут только администраторы.

## Совместная работа

Владелец открывает проект → «Настройки» → «Участники» → «Добавить участника» и отправляет числовой ID пользователя ВК (`123`, `id123`) или ссылку на профиль (`https://vk.com/id123`, `https://vk.com/username`). Короткое имя разрешается через VK API; если метод недоступен токену сообщества, используйте числовой ID. Числовой ID должен принадлежать нужному человеку — сверяйте показанную ссылку. Доступ выдаётся только к выбранному проекту, менять `.env` для приглашённого не нужно. Автоматических личных сообщений приглашённому бот не отправляет: ему нужно самому написать сообществу «Начать».

Роли:

- **Администратор** из `VK_ALLOWED_USERS`: создаёт проекты, видит все проекты и управляет ими. Его общий доступ нельзя снять кнопкой удаления участника.
- **Владелец**: создатель проекта; меняет настройки, добавляет и удаляет участников. Владелец сохраняет эти права даже при удалении его ID из списка администраторов. У проектов из прежней версии без записанного владельца при обновлении владельцем назначается администратор с наименьшим числовым ID; все текущие администраторы по-прежнему могут управлять такими проектами.
- **Участник**: видит только назначенные проекты, выбирает задания, генерирует текст, загружает фото, просматривает общий черновик и отправляет материалы в таблицу. Менять настройки, создавать проекты и назначать других людей не может. Для прямого доступа к закрытой папке Google нужны отдельные права Google; участие в боте само по себе их не меняет.

Список людей в меню «Участники» разбит на страницы. Удаление требует подтверждения и действует сразу: старые кнопки и открытое задание больше не дают доступа. Владелец не может удалить себя. Удаление участника не удаляет общие материалы и не влияет на его доступ к другим назначенным проектам. Доступы сохраняются в SQLite вместе с проектами и переживают перезапуск. Изменение списка людей не сбрасывает задания и настройки других участников.

## Google для каждого проекта

После разовой настройки приложения владелец открывает **проект → «Настройки» → «Подключить Google» → «Войти в Google»**. В браузере выбирает нужный аккаунт и разрешает доступ к Диску и Таблицам. Страница `https://bot.itiscat.ru/oauth/google/callback` завершает подключение, затем можно вернуться к датам в ВК. Таблица и папка выбираются ссылками в настройках того же проекта. Google-аккаунт должен иметь право редактирования таблицы и создания файлов в папке.

У каждого проекта отдельное подключение. Один аккаунт можно использовать в нескольких проектах или подключить разные аккаунты. «Сменить Google-аккаунт» заменяет подключение только выбранного проекта. При смене аккаунта задание нужно открыть заново, новые материалы используют отдельный черновик и не смешиваются с файлами прежнего аккаунта. Участники работают через аккаунт проекта без личной авторизации в Google; менять подключение могут владелец и администратор.

Ссылки входа одноразовые, действуют 10 минут. Новая ссылка отменяет предыдущую для этого проекта. Доступ инициатора повторно проверяется при возврате из Google. Токены хранятся только на сервере в `data/google/` (каталог 700, файлы 600), не попадают в сообщения и журналы callback-сервиса. Резервируйте весь `data/`, включая Google-подключения. У старых проектов сохраняется совместимость с ранее настроенным общим `GOOGLE_CREDENTIALS_FILE`; новые проекты этот общий аккаунт не наследуют и требуют подключения через бот.

Разовая настройка владельцем сервера:

1. В Google Cloud включите **Google Drive API** и **Google Sheets API**, настройте Google Auth Platform (брендинг, аудитория, доступ к данным). Для тестового приложения добавьте Google-аккаунты владельцев проектов в Test users.
2. Создайте OAuth client типа **Web application**. В **Authorized redirect URIs** добавьте точно `https://bot.itiscat.ru/oauth/google/callback`. Desktop client для кнопки в боте не подходит.
3. Загрузите скачанный JSON на сервер в `/opt/bmauto/credentials-web.json`, установите `chmod 600 credentials-web.json`. Не отправляйте JSON в чат и не добавляйте в Git.
4. Добавьте в существующий `.env` (не заменяйте его содержимое):

```dotenv
GOOGLE_OAUTH_CLIENT_FILE=credentials-web.json
GOOGLE_OAUTH_REDIRECT_URI=https://bot.itiscat.ru/oauth/google/callback
GOOGLE_OAUTH_PORT=8787
```

5. В существующий **HTTPS server block** Nginx для `bot.itiscat.ru` добавьте `include /opt/bmauto/deploy/google-oauth.nginx.inc;`, затем проверьте `nginx -t` и перезагрузите Nginx. Фрагмент добавляет только обработчик OAuth, не заменяет сайт или настройки сертификата. Домен должен открываться по HTTPS с действительным сертификатом; одной DNS-записи недостаточно. Callback-путь не должен записываться в access/error логи: URL содержит одноразовый код.
6. Запустите оба процесса: бот `.venv/bin/python -m bmauto.main` и callback `.venv/bin/python -m bmauto.oauth_server` из `/opt/bmauto`. Callback слушает **только 127.0.0.1:8787**, открывать этот порт в интернет не нужно. Готовые systemd units находятся в `deploy/`; установка описана ниже.

При тестовом статусе OAuth refresh tokens могут истекать через 7 дней. Для постоянной работы настройте подходящий production/internal режим и выполните требования Google к проверке приложения. Утилита `python -m bmauto.auth` остаётся для старого способа подключения через Desktop client, но для новых проектов используйте кнопку в боте.

Таблица: первая строка — непустые уникальные заголовки; обязательны настроенные столбцы «Дата», «День недели», «Ссылка». Прочие столбцы свободные. Даты: `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, `ДД/ММ/ГГГГ`, с четырёхзначным годом. Пример:

| Дата | День недели | Задание | Ссылка |
| --- | --- | --- | --- |
| 20.12.2030 | Пятница | Рассказать о новом автомобиле | |

Текущий день исключается; день недели берётся из таблицы. Неверная заполненная дата выдаёт ошибку с номером строки. Уже существующая другая ссылка не перезаписывается. Не перемещайте и не редактируйте выбранные строки во время обработки: перед выгрузкой бот сравнивает задание со снимком. Обновите список дат после изменений.

`public_read: true` означает публичную ссылку на папку и её материалы. При `false` новые публичные разрешения не добавляются, действуют унаследованные права папки; ссылка не даёт доступа посторонним. Ограничения Workspace могут запрещать публичный доступ — бот тогда не запишет ссылку как успешно опубликованную.

## GenAPI: требуется проверка подключения

Провайдер выбран: https://gen-api.ru/. Ключ `GENAPI_API_KEY` вводится только в `.env` или защищённое окружение процесса. `GENAPI_MODEL` задаёт slug модели; `gpt-4o-mini` указан как **предварительный бюджетный кандидат**, а не как подтверждённая самая дешёвая модель в текущем каталоге.

Адаптер изолирован в `bmauto/llm.py`: отправка в `/api/v1/networks/{model}`, получение статуса `/api/v1/request/get/{request_id}`, сообщения `system`/`user`. **Контракт, доступность модели и цены ещё нужно сверить по официальной документации GenAPI и проверить реальным запросом.** Из этой среды документация вернула сетевой запрет 403. Тесты с подменами не подтверждают совместимость с реальным API. При тайм-ауте генерации проверьте статус указанного request_id в GenAPI перед новым платным запросом.

Сетевые назначения для запуска: `api.vk.com`, HTTPS Long Poll сервер, выданный VK, хосты фото VK (`*.userapi.com`, `*.vk.com`, `*.vkuserphoto.ru`), `sheets.googleapis.com`, `www.googleapis.com`, `oauth2.googleapis.com`, `api.gen-api.ru`. Для браузерного OAuth также нужен `accounts.google.com`. Настраивайте доступ через политику среды, без отключения TLS или обхода прокси.

## Запуск и проверка

```sh
cd /workspace/BMauto
.venv/bin/python -m pytest -q
.venv/bin/python -m bmauto.main
```

На сервере в `/opt/bmauto`, после настройки `.env`, OAuth client и HTTPS, остановите прежний бот в терминале (Ctrl+C) и установите постоянный запуск:

```sh
cd /opt/bmauto
cp deploy/bmauto.service /etc/systemd/system/bmauto.service
cp deploy/bmauto-google-oauth.service /etc/systemd/system/bmauto-google-oauth.service
systemctl daemon-reload
systemctl enable --now bmauto bmauto-google-oauth
curl --noproxy 127.0.0.1 http://127.0.0.1:8787/healthz
```

Units рассчитаны на текущую установку от root в `/opt/bmauto`. Проверка `/healthz` подтверждает работу HTTP-сервиса, а не авторизацию Google. Чтобы проверить подключение, откройте проект → «Настройки» → «Подключить Google», завершите вход в браузере и откройте даты. Повторите с другим Google-аккаунтом во втором проекте и убедитесь, что таблицы и папки доступны от соответствующего аккаунта.

Дальнейшие обновления:

```sh
cd /opt/bmauto
git pull --ff-only origin main
systemctl restart bmauto bmauto-google-oauth
systemctl status bmauto bmauto-google-oauth --no-pager
```

Если изменились зависимости, перед перезапуском обновите их по `uv.lock` командой `uv sync --frozen`. Не запускайте второй экземпляр бота рядом с systemd-службой.

Проверка вживую: с разрешённого VK-аккаунта выберите тестовый проект и будущую строку, сгенерируйте текст с дополнением, прикрепите фото, отправьте в таблицу. Откройте ссылку из строки, проверьте Word и изображения; при публичном доступе проверьте в отдельном браузере без авторизации. Повторная отправка не должна создавать файлы заново.

SQLite и фотографии сохраняются в `APP_DATA` (`data/`). Храните эту директорию на постоянном диске и резервируйте вместе с настройками. ID файлов фиксируются перед созданием на Drive, завершённые загрузки отмечаются после ответа. Повтор после сбоя продолжает выгрузку. После начала выгрузки изменение материалов заблокировано, чтобы повтор не смешал версии. Удаление фото/редактирование текста вручную в боте пока не реализованы.

На этапе разработки проверены сценарные тесты с подменами API: весь диалог, раскладка дат в реальном JSON клавиатуры ВК, настройки, совместные черновики, изоляция проектов и отзыв доступа, `.docx`, повтор выгрузки после сбоя Sheets, одноразовые ссылки OAuth с PKCE, права и разделение Google-аккаунтов. Callback-сервис запускался локально: health вернул 200, недействительная ссылка — 400. **Живой вход Google, серверный домен/HTTPS, VK и GenAPI ещё не проверены из этой среды: для них нужны реальные настройки сервера и учётные данные.**

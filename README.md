# BMauto — бот сообщества ВК

Python 3.12+. Задания берутся из Google Таблиц. Текст генерируется через GenAPI, до 9 фотографий принимаются в ВК. Материалы сохраняются на Google Диске, ссылка записывается в строку задания.

## Меню

«Начать» → выбор проекта → даты **в два столбца**, «Настройки» и «Все проекты».

Для создания проекта достаточно названия. В настройках остаются:

- подключение Google;
- ссылка на Google Таблицу;
- концепция;
- промпт для текста;
- участники;
- красная «Удалить проект» с подтверждением и отдельная кнопка «Назад».

Все настройки находятся на одном экране. Выбора вкладок, папки, часового пояса, порога следующего месяца и режима доступа нет. Название задаётся при создании, смена названия отключена. `config.json` не нужен: настройки сохраняются в SQLite. Старый файл поддерживается только для первоначального импорта проектов.

Все кнопки работают через callback: нажатия не отправляют названия действий в чат. Вход в Google также открывается через callback. При запуске бот включает `message_event` в Long Poll, сохраняя остальные подписки сообщества.

Новые ответы бота объединяются в актуальный экран: новый экран сначала отправляется, затем удаляются предыдущие ответы и сообщения о ходе операции. При ошибке отправки старый экран сохраняется. Для длинного текста сохраняются все части текущего экрана. Идентификаторы сообщений хранятся в SQLite, поэтому очистка продолжает работать после перезапуска. Переписка, существовавшая до включения этого режима, не загружается и не удаляется.

Введённые текст и фото удаляются только после успешной обработки. Если ВК запрещает удалять входящее сообщение у всех, бот удаляет его только со стороны сообщества; у отправителя оно может остаться. При ошибке обработки исходный ввод сохраняется для повторной попытки.

## Автоматическая работа с Google

Вкладки называются «Январь», «Февраль», …, «Декабрь»; регистр букв не важен. Бот показывает будущие даты текущего месяца только с непустым заданием в колонке задания. Пустые задания, пробелы и ячейки с одной лишь ссылкой на готовые материалы не показываются. На странице до 8 заданий: первые четыре идут сверху вниз в левом столбце, следующие четыре — в правом. Незаполненные места справа дополняются визуально пустой кнопкой без действия, чтобы даты слева сохраняли ширину столбца. Остальные доступны через «Далее». В последнюю неделю месяца добавляет следующий; если будущих заданий текущего месяца больше нет, следующий подключается сразу. Декабрь → январь учитывает смену года. Дата определяется по московскому времени, ручной настройки часового пояса нет. Старые настройки вкладок и порога больше не влияют на выбор.

Заголовки автоматически определяются **во второй или третьей строке** по столбцам **Дата** и **День недели**. Задания начинаются сразу после заголовков. Название месяца и пустые строки выше заголовков игнорируются. Заголовки должны быть уникальными и непустыми; пустые ячейки справа за последним заголовком допускаются. **Новая структура: A — статус, B — дата, C — время, D — день недели, E — задание.** Колонка «Время» определяется по заголовку и должна стоять сразу после даты. Время публикации записывается как `13:45`. В прежних таблицах без «Время» задание по-прежнему берётся из D. При выборе даты бот показывает также время; в мониторинге оно находится под датой. Другие каналы справа от задания не участвуют в генерации. Вставка колонки сохраняет существующие черновики. Изменение времени в таблице требует повторного открытия задания перед отправкой или согласованием. Даты с годом: `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД` или `ДД/ММ/ГГГГ`. В новой структуре доступны также задания текущего дня; в прежней структуре без времени текущий день исключается. Заметки без даты не попадают в календарь.

Первая ячейка строки **A** используется для статуса вместо номера недели; её заголовок меняется на «Статус». Вертикальные объединения внутри A под заголовком разделяются, чтобы у каждой даты был свой статус. Другие колонки и описание задания сохраняются. При открытии проекта бот записывает текстовые статусы и цветовые правила на всех вкладках, названных по месяцам, включая прошлые месяцы. Повторное открытие не дублирует правила. Согласования будущих дат сохраняются; все прошедшие даты получают серый статус «Дата прошла». Цветовые правила сравнивают текст статуса и не используют формулы с зависимыми от локали разделителями. При записи статуса бот также явно задаёт заливку ячейки и восстанавливает приоритет правил для A. Статусы не содержат формул: даты, ссылки и приоритет согласования рассчитываются в Python. Старые ячейки с ошибками формул автоматически заменяются при обновлении статусов.

- Пустая ячейка без заливки — будущая дата без ссылки на материалы.
- «Запланировано» — жёлтый, только если под заданием добавлена ссылка на материалы.
- «Дата прошла» — серый для всех дат раньше сегодняшнего дня, независимо от задания, ссылки и прежнего согласования. Старые статусы прошедших дат заменяются при обновлении.
- «Согласовано» — зелёный только после подтверждения отложенной публикации в Postmypost по кнопке в меню задания, пока дата не прошла. Без подключения сервиса согласование не выполняется.

Прошедшие даты определяются по московскому времени. Работающий бот обновляет статусы при запуске, при смене календарного дня и при открытии проекта; после сетевой ошибки повторяет фоновое обновление через 5 минут. Для фонового обновления бот должен работать постоянно. Согласование доступно всем участникам проекта после отправки материалов. Несохранённые правки сначала нужно отправить; повторная отправка изменённого текста или фото сбрасывает согласование. Перед записью статуса бот повторно проверяет исходную вкладку, дату, время, задание и ссылку.

Меню задания: просмотр черновика → редактирование / генерация текста → фотографии со счётчиком → отправка или согласование → возврат к датам. В режиме ввода остаются только относящиеся к нему действия и навигация. В списке дат 🟡 означает отправленные на согласование материалы, 🟢 — согласованные. Кнопка «Настройки» доступна только на экране дат проекта. Кнопки возврата называются «Назад». «Назад», «Меню проекта», «Настройки» и «Все проекты» синие, «Создать проект» и «Согласовано» зелёные. Фото сохраняются автоматически, отдельной кнопки сохранения нет. Кнопка отправки зелёная, удаления красные. Нижняя строка меню: синяя «Назад» слева, справа — действие другим цветом. В задании это зелёная «Отправить в таблицу» или «Согласовано», в настройках — красная «Удалить проект», в фото — красная «Удалить все фото», в участниках — зелёная «Добавить участника». Если действия нет, остаётся только «Назад».

Готовая ссылка добавляется **в конец той же ячейки D, под исходным описанием**:

```text
Исходное описание задания

Готовые материалы:
https://drive.google.com/drive/folders/...
```

Исходное описание сохраняется полностью. Отдельные столбцы и строки не создаются, ячейка D следующего дня и остальные каналы не меняются. Повторная отправка одной ссылки не дублирует её. При следующем чтении бот распознаёт блок готовых материалов и не передаёт его в генерацию. Ссылки на исходные фото внутри самого задания сохраняются. После загрузки материалов перед записью повторно проверяются дата и описание D; правки других каналов не мешают отправке. Другая готовая ссылка не перезаписывается. При обновлении прежние черновики сохраняются; для уже выгруженного черновика без ссылки в D повторное нажатие «Отправить в таблицу» восстанавливает ссылку.

Кнопка «Сгенерировать текст» находится в меню выбранной даты. Если концепция или промпт ещё не заполнены, кнопка остаётся видимой и показывает подсказку о заполнении настроек. Участнику предлагается обратиться к владельцу за заполнением этих полей. После настройки можно добавить инструкцию к заданию. Используются концепция, промпт, дата, описание из D и дополнение. Повторная генерация заменяет текст и оплачивается отдельно. «Загрузить фотографии» принимает фото ВК в JPEG, PNG и WebP: несколько вложений в одном сообщении или несколько сообщений подряд, максимум 9 уникальных изображений. Ошибка скачивания одного фото не мешает сохранению остальных; бот сообщает количество ошибок и предлагает прислать фото повторно. Перед сохранением бот получает полный список вложений через API сообщений ВК. Фото с нулевыми или отсутствующими ID различаются по источнику изображения. Повторная доставка сообщения ВК не дублирует материалы; дополненная доставка того же сообщения может добавить недостающие фото. Уже сохранённое фото из старой партии с нулевыми ID распознаётся по содержимому при повторной отправке. Ответ показывает, сколько фото получено от ВК и сколько сохранено; ошибка проверки полного сообщения указывается отдельно. ВК может сжимать фото; документы-вложения пока не принимаются.

«Посмотреть черновик» присылает ссылку на папку материалов в Google Диске. Фотографии повторно в ВК не загружаются. До первой отправки бот подсказывает отправить материалы в таблицу; если после отправки появились локальные правки, рядом со ссылкой выводится напоминание обновить материалы.

«Отправить в таблицу» доступна только в меню задания: после загрузки фото нажмите «Назад». Можно отправить от 1 до 9 фотографий, без ожидания полного набора. Также можно отправить только текст или текст с фото. Пустой черновик не отправляется. Word-файл создаётся, если текст уже сгенерирован; для отправки только фото пустой Word не создаётся.

Отправка автоматически создаёт структуру:

```text
Мой диск/
└── BMauto/
    └── Название проекта/
        └── Дата/
            ├── publication.docx
            ├── photo_01.jpg
            └── …
```

Корень BMauto повторно используется в одном Google-аккаунте. Папки разных проектов разделены по ID проекта, даже если их названия одинаковы. Состояние создания папок сохраняется до запроса к Google, поэтому повтор после сетевого сбоя продолжает операцию. Ранее созданные материалы не перемещаются.

**Каждая папка даты автоматически доступна всем по ссылке на чтение**, включая её изображения и Word-файл. Это обязательная часть отправки, переключателя нет. Корень BMauto и общая папка проекта публичными не делаются. После загрузки и настройки доступа ссылка записывается в исходную вкладку и строку задания. Идентификатор вкладки сохраняется: переход месяца или переименование вкладки не изменят место записи. Если Workspace запрещает публичный доступ, бот не отметит отправку успешной и не запишет новую ссылку.

Другая существующая ссылка не перезаписывается. Изменённое задание требует повторного выбора даты. Черновик можно редактировать и после отправки: «Редактировать текст» заменяет текст целиком, «Сгенерировать текст» создаёт новую версию, «Фотографии» позволяет добавить фото, удалить отдельные или убрать все и загрузить замену. После правок появляется зелёная «Отправить в таблицу» — название одинаково для первой и повторной отправки. Сохранение обновляет файлы в той же папке даты, сохраняя её адрес и ссылку в таблице. Удалённые из черновика фотографии перемещаются в корзину Диска при сохранении; файлы, добавленные в папку вручную, не затрагиваются. Повтор отправки восстанавливает незавершённую операцию без дубликатов. Общие черновики и фото переживают перезапуск.

## Соцсети и отложенные публикации Postmypost

В настройках каждого проекта есть **«Соцсети · Postmypost»**. Владелец или администратор подключает API-токен, выбирает проект Postmypost, отмечает несколько соцсетей и нажимает «Сохранить». Сами социальные аккаунты сначала подключаются в кабинете Postmypost; API бота выбирает уже подключённые аккаунты. Участники проекта могут согласовывать публикации с этим подключением, но не получают токен и не меняют получателей. Токен хранится отдельно от настроек проекта в закрытой SQLite-базе с правами 600; в сообщениях и мониторинге он не показывается.

Колонка C **«Время»** должна содержать время публикации, например `13:45` (`13:45:00` также поддерживается). Дата и время интерпретируются по Москве и передаются API с явным UTC-смещением. Задания текущего дня доступны; прошедшее время и пустая/неверная ячейка блокируют отправку. Черновик можно подготовить и сохранить на Google Диск до заполнения времени.

После «Отправить в таблицу» нажмите **«Согласовано»**. Бот проверяет актуальные задание, дату, время, ссылку и получателей, загружает все фотографии и создаёт одну отложенную запись для всех выбранных соцсетей (`publication_type=1`, `publication_status=5`). Затем отдельным GET проверяет ID, очередь, дату/время, полный список получателей, текст и файлы. Только после подтверждения записывает зелёное «Согласовано» в A. Это подтверждение очереди Postmypost, а не фактического выхода поста в соцсетях. Ошибка или неполное подтверждение оставляют статус таблицы прежним.

ID записи сохраняется до проверки статуса и записи в Google. После сбоя чтения или записи таблицы повторная кнопка проверяет ту же запись. Изменённые текст, фотографии или время обновляют её через PUT, сохраняя ID. Изменение соцсетей/токена требует заново открыть задание. Переключение на другой проект Postmypost для черновика с существующей очередью блокируется до ручной сверки прежней записи. Если ответ создания потерялся и ID неизвестен, повторный POST блокируется во избежание дубля; нужна ручная сверка кабинета. Записи, уже находящиеся в отправке или опубликованные, бот не переписывает. Удаление проекта в боте не отменяет ранее созданную внешнюю очередь.

Клиент основан на [CanDreamm/The-Loremaster](https://github.com/CanDreamm/The-Loremaster/blob/6c5526496b8e221df774a3443c865a4f72012dae/publikot/postmypost.py) и сверён с [официальным SDK Postmypost](https://github.com/postmypost/python-rest-sdk). Загрузка проходит init → отдельный multipart-запрос без API-токена → complete → status. Для запросов действуют отдельные ограничения частоты; создание автоматически не повторяется. Новые зависимости или изменения Nginx не нужны. Рабочий сервер должен иметь HTTPS-доступ к `api.postmypost.io` и хранилищу, возвращённому `/upload/init`.

## Личный мониторинг участника

В общем списке проектов нажмите **«Мой мониторинг»**. Бот выдаёт постоянную личную секретную ссылку `https://bot.itiscat.ru/monitor/…`. У каждого участника своя ссылка; она сохраняется после перезапуска и при добавлении проектов. Каждый может сменить только собственную ссылку с подтверждением. Прежний личный адрес сразу перестаёт работать.

Вверху страницы — вкладки всех проектов, доступных этому человеку в боте; внизу — месяцы выбранного проекта. Администраторы видят все проекты согласно своим правам. Проверка назначений выполняется при каждом запросе, до доступа к кешу и после чтения Google. При исключении участника проект исчезает из его мониторинга; при добавлении — появляется по той же ссылке. Удалённые проекты недоступны. Если доступных проектов больше нет, страница остаётся пустой и не раскрывает чужие данные.

Дополнительно владелец или администратор может открыть **проект → Настройки → Мониторинг проекта** и получить отдельную секретную ссылку для передачи людям, которым нужен просмотр только этого проекта. Она постоянная, не зависит от личных ссылок участников и не позволяет открыть другие проекты даже через параметры адреса. Кнопка «Сменить ссылку» с подтверждением закрывает прежний адрес для всех получателей. Удаление проекта также закрывает доступ. Права на создание и смену ссылки проверяются в боте; просмотр по самой ссылке доступен без входа и только для чтения.

Старые ссылки из прежней версии `monitor_links` остаются отключёнными: новые ссылки проектов создаются отдельно, без восстановления ранее выданных адресов.

Проекты расположены отдельными кнопками вверху, месяцы — внизу. Каждая строка контент-плана оформлена отдельной плашкой с датой, днём недели и заданием; шапка страницы и заголовки столбцов скрыты. Светлая заливка всей плашки повторяет смысл цветов Google Таблицы: жёлтый — «Запланировано», зелёный — «Согласовано» и «Вышло», красный — «Не запланировано», серый — «Нет публикации». Строки без статуса остаются белыми. Легенда статусов не показывается. Подписи «Ожидает согласования», «Подготовить материалы» и «Задание не задано» выделены жирным и более тёмным оттенком заливки плашки. «Материалы» выделены кнопкой. Название статуса доступно программе чтения с экрана. На телефоне дата и день располагаются над заданием без горизонтальной прокрутки. Показываются даты начиная с сегодняшнего дня (по московскому времени) из колонок статуса, даты, времени, дня недели и задания, включая дни без задания; другие каналы таблицы не публикуются. Статусы читаются непосредственно из Google Таблицы и через сайт не изменяются. У каждого проекта используется его собственное подключение Google; ошибка подключения одного проекта не мешает открыть остальные вкладки.

Данные обновляются раз в минуту; кнопка «Обновить» сразу перечитывает Google. Обычные чтения кешируются до 30 секунд, но список проектов и права доступа не кешируются. На телефоне вкладки проектов и месяцев прокручиваются по горизонтали. Сайт принимает только GET/HEAD, запросы изменения отклоняются.

Личный адрес содержит случайный ключ на 256 бит и предоставляет доступ ко всем проектам участника: не передавайте его посторонним. Ключ не содержит ID пользователя; страницы не индексируются, не кешируются браузером и не передают Referer. Секретные маршруты не записываются в журналы Nginx.

Мониторинг работает в службе `bmauto-google-oauth` на localhost:8787. После обновления перезапустите обе службы:

```bash
cd /opt/bmauto
git pull --ff-only origin main
systemctl restart bmauto bmauto-google-oauth
```

Маршруты `/monitor/` и `/monitor-assets/` в `deploy/google-oauth.nginx.inc` остаются прежними. Если мониторинг устанавливается впервые, в HTTPS-блоке Nginx нужен `include /opt/bmauto/deploy/google-oauth.nginx.inc;`, затем `nginx -t && systemctl reload nginx`. Новый порт и сертификат не требуются.

## Совместная работа

Владелец: проект → «Настройки» → «Участники» → «Добавить участника». Отправьте числовой ID ВК или ссылку на профиль. Приглашённому нужно самому написать сообществу «Начать»; автоматических личных сообщений бот не отправляет. Добавлять человека в `.env` не нужно.

- Администраторы из `VK_ALLOWED_USERS` создают проекты и управляют всеми проектами.
- Владелец меняет концепцию, промпт и таблицу, назначает людей и удаляет проект.
- Участник видит только назначенные проекты, работает с общими черновиками, отправляет материалы и может подключить свой Google. Назначать других людей, удалять проект и менять остальные параметры он не может.

**Google-аккаунт общий для выбранного проекта.** Подключение участником своего аккаунта заменяет предыдущее подключение этого проекта, другие проекты не меняются. Таблица должна быть доступна подключённому аккаунту на редактирование. Во время входа бот объясняет область действия подключения.

Удаление участника действует сразу, включая старые кнопки и незавершённые ссылки OAuth. Удаление проекта требует подтверждения, закрывает доступ всем участникам и сбрасывает открытые задания. Диск и таблица сохраняются. В локальной базе остаётся архивная отметка, черновики и фото; старый конфигурационный файл не восстановит удалённый проект автоматически.

## Установка

```sh
cd /workspace/BMauto
uv sync --frozen --extra test
cp -n .env.example .env
```

Не перезаписывайте существующий `.env`. Заполните `VK_TOKEN`, `VK_GROUP_ID`, `VK_ALLOWED_USERS`, `GENAPI_API_KEY`. В сообществе ВК включите сообщения, клавиатуры и Bots Long Poll с событием `message_new`. Нужен токен сообщества с правами для сообщений и `groups.getLongPollServer`.

GenAPI используется через `bmauto/llm.py`. Модель задаётся в серверном `GENAPI_MODEL`; `gpt-4o-mini` — предварительный бюджетный кандидат. Доступность модели, текущие цены и реальный контракт GenAPI требуют проверки с действующим ключом. После тайм-аута проверьте статус request_id у провайдера до повторной платной генерации.

## Разовая настройка Google OAuth на сервере

1. В Google Cloud включите Google Drive API и Google Sheets API. Настройте Google Auth Platform. Для тестового приложения добавьте в Test users Google-аккаунты всех людей, которые будут подключать Google.
2. Создайте OAuth client типа **Web application** и задайте Authorized redirect URI:

   ```text
   https://bot.itiscat.ru/oauth/google/callback
   ```

3. Скачайте JSON и загрузите его на сервер как `/opt/bmauto/credentials-web.json`; задайте права `chmod 600 credentials-web.json`. Desktop JSON не подходит. Файл не отправляйте в чат и не добавляйте в Git.
4. В `.env` используются следующие параметры (добавьте их, сохранив остальные значения):

   ```dotenv
   GOOGLE_OAUTH_CLIENT_FILE=credentials-web.json
   GOOGLE_OAUTH_REDIRECT_URI=https://bot.itiscat.ru/oauth/google/callback
   GOOGLE_OAUTH_PORT=8787
   ```

5. В существующий HTTPS server block Nginx для `bot.itiscat.ru` добавьте:

   ```nginx
   include /opt/bmauto/deploy/google-oauth.nginx.inc;
   ```

   Проверьте `nginx -t` и перезагрузите Nginx. Фрагмент добавляет Google callback и страницы мониторинга, сохраняя остальные маршруты и TLS. Он отключает логирование маршрута, URL которого содержит одноразовые коды. Порт 8787 слушает только localhost и не требует открытия в интернет.

После этого любой назначенный участник: проект → «Настройки» → «Подключить Google» → вход в браузере → разрешение доступа к Диску и Таблицам. Ссылки одноразовые, действуют 10 минут; новая ссылка отменяет старую. Доступ к проекту проверяется до и после обмена кодом. Токены остаются на сервере в `data/google/` (каталог 700, файлы 600). Для тестового статуса Google refresh tokens могут истекать через 7 дней; постоянный запуск требует подходящего production/internal режима и выполнения требований Google к проверке приложения.

## Запуск на сервере

Остановите старый бот в терминале через Ctrl+C перед установкой службы. Запускайте один экземпляр бота на одну базу. Обработка последовательная; генерация временно задерживает следующие сообщения.

```sh
cd /opt/bmauto
cp deploy/bmauto.service /etc/systemd/system/bmauto.service
cp deploy/bmauto-google-oauth.service /etc/systemd/system/bmauto-google-oauth.service
systemctl daemon-reload
systemctl enable --now bmauto bmauto-google-oauth
```

Units рассчитаны на текущую установку от root в `/opt/bmauto`. Проверка обработчика:

```sh
curl --noproxy 127.0.0.1 http://127.0.0.1:8787/healthz
```

Она подтверждает работу HTTP-сервиса, а не вход в Google. Живая проверка: подключите аккаунт из бота, укажите таблицу, выберите будущую дату, сгенерируйте текст, прикрепите фото и отправьте. Проверьте путь BMauto/Проект/Дата, Word и фотографии, ссылку в нужной строке и её открытие без авторизации Google. Повтор отправки не должен создавать файлы заново.

Обновление:

```sh
cd /opt/bmauto
git pull --ff-only origin main
systemctl restart bmauto bmauto-google-oauth
```

При изменении зависимостей перед перезапуском выполните `uv sync --frozen`. Для ручного запуска: `.venv/bin/python -m bmauto.main`; не запускайте его одновременно со службой.

## Данные и проверка разработки

`APP_DATA` (`data/`) хранит проекты, доступы, черновики, фото, OAuth и кэш созданных папок. Директория должна быть постоянной; резервируйте её целиком. Секреты и локальные данные исключены из Git. Старые локальные настройки сохраняются для совместимости, но удалённые из меню параметры папки, доступа, вкладок, времени и перехода месяца больше не управляют автоматическим сценарием.

```sh
.venv/bin/python -m pytest -q
```

Тесты используют подмены внешних API: диалог ВК, права и удаление, месяцы и годы, независимые аккаунты Google, OAuth/PKCE, автоматические папки и повторы после сбоя, публичную ссылку и запись в исходную строку. Callback запускался локально и проверялся HTTP-запросами. Живые VK/Google/GenAPI из рабочей среды без учётных данных не проверены; состояние на сервере проверяется отдельно.

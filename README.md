# BMauto — бот сообщества ВК

Python 3.12+. Задания берутся из Google Таблиц. Текст генерируется через GenAPI, до 9 фотографий принимаются в ВК. Материалы сохраняются на Google Диске, ссылка записывается в строку задания.

## Меню

«Начать» → выбор проекта → даты **в два столбца**, «Настройки» и «Все проекты».

Для создания проекта достаточно названия. В настройках остаются:

- подключение Google;
- концепция;
- промпт для текста;
- ссылка на Google Таблицу;
- участники;
- «Назад» и красная «Удалить проект» с подтверждением.

Все настройки находятся на одном экране. Выбора вкладок, папки, часового пояса, порога следующего месяца и режима доступа нет. Название задаётся при создании, смена названия отключена. `config.json` не нужен: настройки сохраняются в SQLite. Старый файл поддерживается только для первоначального импорта проектов.

## Автоматическая работа с Google

Вкладки называются «Январь», «Февраль», …, «Декабрь»; регистр букв не важен. Бот показывает будущие заполненные даты текущего месяца. В последнюю неделю месяца добавляет следующий; если будущих заданий текущего месяца больше нет, следующий подключается сразу. Декабрь → январь учитывает смену года. Дата определяется по московскому времени, ручной настройки часового пояса нет. Старые настройки вкладок и порога больше не влияют на выбор.

В таблице первая строка — уникальные непустые заголовки. Стандартные столбцы: **Дата**, **День недели**, **Ссылка**. Остальные поля задания свободные. Даты с годом: `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД` или `ДД/ММ/ГГГГ`. Текущий день исключается. При выборе задания показываются все его непустые поля.

По кнопке «Сгенерировать текст» можно добавить инструкцию к заданию. Используются концепция, промпт, поля строки и дополнение. Повторная генерация заменяет текст и оплачивается отдельно. «Загрузить фотографии» принимает JPEG-фото ВК несколькими сообщениями, максимум 9 уникальных изображений. ВК может сжимать фото; документы-вложения пока не принимаются.

«Отправить в таблицу» автоматически создаёт структуру:

```text
Мой диск/
└── BMauto/
    └── Название проекта/
        └── Дата/
            ├── publication.docx
            ├── photo_01.jpg
            └── …
```

Корень BMauto повторно используется в одном Google-аккаунте. Папки разных проектов разделены по ID проекта, даже если их названия одинаковы. Состояние создания папок сохраняется до запроса к Google, поэтому повтор после сетевого сбоя продолжает операцию. Ранее созданные материалы не перемещаются.

**Каждая папка даты автоматически доступна всем по ссылке на чтение**, включая её изображения и Word-файл. Это обязательная часть отправки, переключателя нет. Корень BMauto и общая папка проекта публичными не делаются. После загрузки и настройки доступа ссылка записывается в исходную вкладку и строку задания. Идентификатор вкладки сохраняется: переход месяца или переименование вкладки не изменят место записи. Если Workspace запрещает публичный доступ, бот не отметит отправку успешной и не запишет новую ссылку.

Другая существующая ссылка не перезаписывается. Изменённое задание требует повторного выбора даты. После начала выгрузки материалы зафиксированы; повтор отправки восстанавливает незавершённую операцию без дубликатов. Общие черновики и фото переживают перезапуск.

## Совместная работа

Владелец: проект → «Настройки» → «Участники» → «Добавить участника». Отправьте числовой ID ВК или ссылку на профиль. Приглашённому нужно самому написать сообществу «Начать»; автоматических личных сообщений бот не отправляет. Добавлять человека в `.env` не нужно.

- Администраторы из `VK_ALLOWED_USERS` создают проекты и управляют всеми проектами.
- Владелец меняет концепцию, промпт и таблицу, назначает людей и удаляет проект.
- Участник видит только назначенные проекты, работает с общими черновиками, отправляет материалы и может подключить свой Google. Назначать других людей, удалять проект и менять остальные параметры он не может.

**Google-аккаунт общий для выбранного проекта.** Подключение участником своего аккаунта заменяет предыдущее подключение этого проекта, другие проекты не меняются. Таблица должна быть доступна подключённому аккаунту на редактирование. Во время входа бот объясняет область действия подключения.

Удаление участника действует сразу, включая старые кнопки и незавершённые ссылки OAuth. Удаление проекта требует подтверждения, закрывает доступ всем участникам и сбрасывает открытые задания. Диск и таблица сохраняются. В локальной базе остаётся архивная отметка, черновики и фото; старый конфигурационный файл не восстановит удалённый проект автоматически.

## Установка

```sh
cd /workspace/BMauto
uv sync --frozen --extra test
cp -n .env.example .env
```

Не перезаписывайте существующий `.env`. Заполните `VK_TOKEN`, `VK_GROUP_ID`, `VK_ALLOWED_USERS`, `GENAPI_API_KEY`. В сообществе ВК включите сообщения, клавиатуры и Bots Long Poll с событием `message_new`. Нужен токен сообщества с правами для сообщений и `groups.getLongPollServer`.

GenAPI используется через `bmauto/llm.py`. Модель задаётся в серверном `GENAPI_MODEL`; `gpt-4o-mini` — предварительный бюджетный кандидат. Доступность модели, текущие цены и реальный контракт GenAPI требуют проверки с действующим ключом. После тайм-аута проверьте статус request_id у провайдера до повторной платной генерации.

## Разовая настройка Google OAuth на сервере

1. В Google Cloud включите Google Drive API и Google Sheets API. Настройте Google Auth Platform. Для тестового приложения добавьте в Test users Google-аккаунты всех людей, которые будут подключать Google.
2. Создайте OAuth client типа **Web application** и задайте Authorized redirect URI:

   ```text
   https://bot.itiscat.ru/oauth/google/callback
   ```

3. Скачайте JSON и загрузите его на сервер как `/opt/bmauto/credentials-web.json`; задайте права `chmod 600 credentials-web.json`. Desktop JSON не подходит. Файл не отправляйте в чат и не добавляйте в Git.
4. В `.env` используются следующие параметры (добавьте их, сохранив остальные значения):

   ```dotenv
   GOOGLE_OAUTH_CLIENT_FILE=credentials-web.json
   GOOGLE_OAUTH_REDIRECT_URI=https://bot.itiscat.ru/oauth/google/callback
   GOOGLE_OAUTH_PORT=8787
   ```

5. В существующий HTTPS server block Nginx для `bot.itiscat.ru` добавьте:

   ```nginx
   include /opt/bmauto/deploy/google-oauth.nginx.inc;
   ```

   Проверьте `nginx -t` и перезагрузите Nginx. Фрагмент добавляет только callback, сохраняя сайт и TLS. Он отключает логирование маршрута, URL которого содержит одноразовые коды. Порт 8787 слушает только localhost и не требует открытия в интернет.

После этого любой назначенный участник: проект → «Настройки» → «Подключить Google» → вход в браузере → разрешение доступа к Диску и Таблицам. Ссылки одноразовые, действуют 10 минут; новая ссылка отменяет старую. Доступ к проекту проверяется до и после обмена кодом. Токены остаются на сервере в `data/google/` (каталог 700, файлы 600). Для тестового статуса Google refresh tokens могут истекать через 7 дней; постоянный запуск требует подходящего production/internal режима и выполнения требований Google к проверке приложения.

## Запуск на сервере

Остановите старый бот в терминале через Ctrl+C перед установкой службы. Запускайте один экземпляр бота на одну базу. Обработка последовательная; генерация временно задерживает следующие сообщения.

```sh
cd /opt/bmauto
cp deploy/bmauto.service /etc/systemd/system/bmauto.service
cp deploy/bmauto-google-oauth.service /etc/systemd/system/bmauto-google-oauth.service
systemctl daemon-reload
systemctl enable --now bmauto bmauto-google-oauth
```

Units рассчитаны на текущую установку от root в `/opt/bmauto`. Проверка обработчика:

```sh
curl --noproxy 127.0.0.1 http://127.0.0.1:8787/healthz
```

Она подтверждает работу HTTP-сервиса, а не вход в Google. Живая проверка: подключите аккаунт из бота, укажите таблицу, выберите будущую дату, сгенерируйте текст, прикрепите фото и отправьте. Проверьте путь BMauto/Проект/Дата, Word и фотографии, ссылку в нужной строке и её открытие без авторизации Google. Повтор отправки не должен создавать файлы заново.

Обновление:

```sh
cd /opt/bmauto
git pull --ff-only origin main
systemctl restart bmauto bmauto-google-oauth
```

При изменении зависимостей перед перезапуском выполните `uv sync --frozen`. Для ручного запуска: `.venv/bin/python -m bmauto.main`; не запускайте его одновременно со службой.

## Данные и проверка разработки

`APP_DATA` (`data/`) хранит проекты, доступы, черновики, фото, OAuth и кэш созданных папок. Директория должна быть постоянной; резервируйте её целиком. Секреты и локальные данные исключены из Git. Старые локальные настройки сохраняются для совместимости, но удалённые из меню параметры папки, доступа, вкладок, времени и перехода месяца больше не управляют автоматическим сценарием.

```sh
.venv/bin/python -m pytest -q
```

Тесты используют подмены внешних API: диалог ВК, права и удаление, месяцы и годы, независимые аккаунты Google, OAuth/PKCE, автоматические папки и повторы после сбоя, публичную ссылку и запись в исходную строку. Callback запускался локально и проверялся HTTP-запросами. Живые VK/Google/GenAPI из рабочей среды без учётных данных не проверены; состояние на сервере проверяется отдельно.
